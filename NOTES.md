# ClipArtCraft notes

- Started 2026-10-31 as the shared library for the Craft apps (the apps keep their own copies of code; the library data is what is shared).
- Works both ways: offline from disk (Chrome/Edge share browser storage between file:// pages) and hosted together on one site.
- Library format is the one ImageCraft's Split a sheet exports (library.json + PNG/SVG).
- ImageCraft's Split a sheet adds straight into the library (Add to the clip-art library, with a category).
- Montage Slicer (js/slicer.js, window.ClipArtSlicer): a copy of ImageCraft's splitSheet/sheetItem (Lab paper model from a 3% border ring, grow by gap/2, connected parts, reading order, exterior-only background removal, defringe) plus a Grid mode (rows × columns, inset per cell; each cell's picture found with one join-everything split and cut out). Click a box to leave it out. Settings except names and category are kept in localStorage.
- Slicer always makes an SVG. SVG sheets: drawn at 2,000–4,000 px to find boxes; svgCut keeps shapes whose root-space bbox (getBBox × getScreenCTM relative to the root) meets the box, drops shapes covering half the sheet (the background), and sets the viewBox to the box. Each cut remembers its box on the sheet (img.at).
- Grid: contentBox() leaves plain margins off (corner colour, tolerance 40). Test sheets: glossy remakes cut cleanly by Find; flat icons on white tiles lose white parts (tile white = paper white); coloured cells with long shadows need Grid (36/36, shadows gone).
- Next: an "Insert clip art…" picker for the other apps (each its own copy), tags and categories from Print Shop-style groups, maybe guess the grid size by itself.
- 2026-10-31 clip-art server (server/): clipart-server.js (Node 22.5+, node:sqlite built in; MySQL/MariaDB through the optional mysql2 package) and clipart-server.php (PDO: SQLite or MySQL/MariaDB), the same API (server/API.md). A library = database + files folder; JSON + files is the export/import/moving format; `copy FROM TO` moves between them. Names unique per library (_002…). CORS open; writes from localhost or with the x-craft-key header. Columns added later (type, style, form) are added to old databases on open. Tested: Node+SQLite, PHP 8.2+SQLite and PHP+MariaDB 10.11 (throwaway Docker containers) give identical answers. Node+MySQL (mysql2) not tested yet.
- Item types: clipart and model (3D mesh in the `model` file; png/thumb are pictures of it). Rendering a model at an angle in the app is still to do.
- Import pictures (js/importer.js, js/formats.js = own copy of ImageCraft's readers + pages(): TIFF pages, ICO sizes, animation frames via ImageDecoder). Kind (colour/grey/bw) from chroma and two-tone share; bw → ink (alpha from darkness; white ink on dark paper). Copies by 64-bit difference hash (Hamming ≤ 4). Seamless = opposite edges as alike as neighbouring columns, and edges not plain. JPEG 2000 / JPEG XL need decoders (not added; the browser is tried first).
- Naming (js/namer.js): CLIP ViT-B/32 q8 on wasm; ~700 words in 22 categories, plus styles, forms and eras as prompts; word directions worked out once and cached (Cache API 'clipartcraft-ai'). Plain cosine works better than centring for picture-to-word. Smart naming = file words when real (camera/scanner names and words like page/scan are ignored), else the AI's.
- Working area (js/work.js, IndexedDB 'craft-clipart-work'): sources kept with a "made" count; the slicer and importer add to it; items carry `sheet` (the source id).
- Next: render 3D models at an angle; montage sheet maker (pages of chosen clip art, packs); "Insert clip art…" picker for the other apps; JP2/JXL decoders (ask first); PDF pages; sheets on the server.
- Setup page (server/setup.html, served at /setup by both servers): admin login (PBKDF2-SHA256, 100k rounds, hex; Node pbkdf2Sync and PHP hash_pbkdf2 give the same), connections list (sqlite/mysql/json; PHP has no json), Test (opens it, makes the MySQL database if missing: 1049 → CREATE DATABASE utf8mb4), Save (a connection without password keeps its saved one, matched by id), Copy (both names must exist). Settings in clipart-settings.php ("<?php exit; ?>" first line + JSON), shared by Node and PHP; old clipart-server.json / clipart-config.php are moved over once. Tested on PHP 8.2 + MariaDB 10.11 (Docker) with real clicks, and Node (setup from another address). Node + MySQL needs mysql2 (not installed).
- Slicer 2026-11-01: two checkboxes in both modes, cut (sheetItem / gridItem cut) and see (see-through); whole box + see = boxClear (flood from the box edges over the corner colour within "how close", default 16, then defringe) — keeps app tiles' own shape and colour, white tiles too (40 loses them). Live result view draws every cut over a checkerboard (off-screen, cancelled when settings change). Review before adding: doubts() per picture (≥90% clear, nothing clear, touching the box edge, very small, cut-out lost >2% of what a strict box clear keeps) + on sheets of ≥4, smaller than 92% of the median size. Sheet 6 (tiles): Find flags 3, 4, 9; Grid + cut off + see on flags none.
- Leaving mid-job (2026-11-01, the user's mouse slipped and refreshed during a send): CraftClipart.guard() wraps long jobs (import add, slicer add, push, pull) with a beforeunload warning; push keeps meta 'pushQueue' (ids still to send, one removed per success), and after a reload ClipArtCraft shows "N pictures were still being sent… Finish sending / Forget it". The importer and slicer save their source files to the working area before adding pictures. Tested: Stay → the send carries on; Leave → 7 of 12 left, Finish sending sent exactly those 7.
- Slicer auto (2026-11-01): autoCut(sheet) on every load (ignores the last sheet's settings): gutters (lines ≥98.5% plain page, tolerance 30, inside the content box; cells even within 80%) → grid; cells >55% filled → tiles (cut off, see on, tol 16) else cut out; no gutters → Find, unless Find joins pictures (largest > 2.5 × median area), then the edge-strength profile's autocorrelation gives the touching cells (≤16 a side, between n and 3n of Find's count). Samples: 1,2,3,4,5,8,9 Find (11, 8, 9, 9, 36, 36, 36), 6 tiles 3×3, 7 touching 6×6. Room at the edges: S.edges per side auto/on/off (yellow/blue/grey), roomPx; edgeRoom pads with see-through; auto only counts with See-through on.
- Still to do (2026-11-01): working-area sources carry pending 'import' | 'slice' from the moment a file is opened in the importer or loaded in the slicer until something is added (or the add finishes); with the push queue they make the Still to do list at the top on load: Send / Process (reopens the importer or slicer with the file) / Cancel (a file nothing was made from leaves the working area), and Flush all.
- Sorting (2026-11-01): the left menu is All, the category list (always, empty ones dimmed, each a branch opening to its subjects = names without numbering), Not sorted yet, Sort N with AI, From sheets and files (each opening to its categories), Working area. Sheet names are no longer categories (the slicer leaves the category empty). sortWithAI (CraftNamer) sets category/style/form/tags, keeps the AI's top 5 guesses on the item (it.ai), renames placeholder names (Sheet 6 – 3, IMG_2041, Clip art – 12); new pictures are sorted at once when the model is already downloaded. Properties: category/style/form drop-downs from the lists, the AI's guesses as chips (click: name + category), Ask the AI again. Lists: CraftClipart.lists() in the shared meta store; CraftNamer.configure() rebuilds the words (cache key = hash of the words). Edit the lists… window: categories with their words, styles, forms, back to the starting lists.
- Slicer find: splitJoined (a found picture over twice the usual size is relabelled by what truly touches, 8-way; ≥2 big parts → separate pictures, small bits to the nearest) then combine (small pieces join the big picture within ~1.2% of the sheet; specks dropped). 3.jpg (Americana, medal and boat) 9 → 11; all other samples unchanged. New sheets also reset min 0.2% and room 6. The light-parts check only on plain pages (edge brightness spread < 4). Code-like file names (GUIDs, long numbers) give "Clip art – n".
- Learning from corrections (2026-11-01): sorting keeps each picture's CLIP picture vector (it.vec, 512 numbers; not sent to the server). Changing one picture's name, category, style or form, or picking one of the AI's guesses, stores a lesson { id, vec, name (subject), category, style, form } in the shared meta 'lessons' (last 2,000) and adds a new name word to that category's words (CraftNamer.learnWord, saved in the lists). name() compares a new picture with the lessons: cosine > 0.86 → the user's answer; > 0.78 → offered as the first guess ("learnt"). Forget my corrections in the lists window. Tested: cart corrected to Stagecoach / Transportation & travel → its mirrored, smaller copy came out Stagecoach_002 in Transportation & travel. Starting list gained stagecoach, covered wagon, horse carriage, horse and buggy, wagon, carriage.
- Describer (2026-11-01): Florence-2-base-ft (onnx-community, MIT) via Transformers.js, <CAPTION>; WebGPU with fp16/q4 parts, else wasm q8 (~260 MB; ~17 s a picture on a CPU, much quicker on a GPU). The subject is taken from the sentence (subjectOf: drops "a drawing of", "the image shows", stops at with/on/holding/…ed/…ing, drops age/size/colour words) and becomes the name and Seen as; its category is the nearest word by meaning ("an illustration of a …" like the word list). Tried swapping general subjects (man, sign) for the matcher's or the sentence's nearest word: worse (Roman soldier, No entry sign, Plus sign), so the described subject stays and the matched words are guesses + tags. Words read on the picture ("says …") go to the tags. Each picture keeps original (the name it came with), seen, matched, description; search looks in all of them; the server has the columns too.
- Cloud AI (2026-11-01, js/cloud.js, window.CraftCloud): for the pictures the AI here gets wrong (user: a button, used only when needed). The user's own key for Claude, Gemini, GPT or OpenRouter, typed into Cloud AI settings and kept in localStorage `clipartcraft-cloud` (never on the server or in files); requests go straight to that company. A 768 px JPEG on white and a prompt with the current lists; answer as JSON (name, category, style, form, tags, description, text). Category, style and form only count when they are words on the lists. The answer is taken as a correction: name (numbered if taken; the old name kept as Original), Seen as, tags, description, `it.cloud` = model, and the AI here learns from it (teach) when the picture has a vector. Model: the one picked, or a quick cheap one (Haiku, Flash, a mini). Opened from files, ClipArtCraft and ImageCraft share localStorage, so the settings offer ImageCraft's keys.
- Slicer tools (2026-11-01, after the user's Copilot "Designer" sheets: style tables, title + heading row + label column, photo columns; and "every agent makes them differently", so hand tools matter as much as finding):
  - `work` = the main area cropped from the sheet, ruled-out boxes and left-out text painted with the page (see-through on a see-through sheet); everything finds and cuts from it; (wx, wy) its place. Boxes keep `key` (where found, sheet px); `moved` (key → rect), `prefs` (noShadow, whole, boxOnly, cutOut) and `splits` (key → k, down; parts keyed key/i) survive re-finding.
  - Table: ruleLines = lines smooth along themselves (step < 6) and differing from the line 2 away (> 8) over ≥ 60%; fainter() looks again inside cells ≥ 1.6× the narrowest (score with diff 4 ≥ 0.3 and ≥ 2.5× the cell's median), columns with no line at all use period(); evenSplit for k× the median. Kinds: short rows (< 0.7 median) at top = head, bottom = foot, between = caption (or gap); first column = label when < 0.75 median wide or its ring colour differs > 40 from the cells; last only when narrow. Photo cells: < 70% of the cell's edge within 12 of its median → kept whole. autoCut tries the old finder first: a gutter grid wins; touching cells win when the table has more cells than them. All 66 Designer sheets + Print Shop sheets found as tables; old samples 1–9 unchanged.
  - Text: sheetText (find mode) = parts < 0.35 × usual height, wider than tall, centred under a picture, letter-like (≥ 2 column runs, fill 12–75%), and on ≥ 40% of the pictures; textBits per cell = above or below the picture, centred. Captions own the picture above; read by Florence-2 `<OCR>` (CraftNamer.read).
  - Sheet information: metaOf(box) → subject (row label, brackets → tag), heading (tag; styleFor maps words to a style on the lists), sheet title (collection), place; name "Row – Heading" (dupes _002); item gets style, description, collection, place, original/seen = subject, checked. PNG gets iTXt chunks (Title, Description, Keywords, Source, Collection, Software) after IHDR.
  - View: zoom relative to fit (wheel round the mouse), middle-button pan, Fit/100% (Ctrl+0/1), turn/flip/straighten (resets the sheet's finding), status bar. Right-click menus via js/menu.js (CraftMenu, submenus, keys).
- Library (2026-11-01): right-click menus on tiles (one or several) and on the left list; Properties window mirrors #details (same handlers, synced on render); F2, Alt+Enter, Ctrl+C. Dark pictures (mean lum of opaque < 80, < 12% light) get a light checkerboard (.lit). The describer's subject is ignored when it is only colours or a kind of picture ("Black", "icon"), so the matched word names it.
- Doing it by itself (user: "5 hours, 1,200+ pictures today"): the slicer takes several files (queue; adding opens the next, done(..., { more })), reads labels on open when S.autoread and the describer is downloaded (readLabels quiet; stops if the sheet changes; progress on the button), S.quick adds without the review when no picture has doubts. Reading: each part is put on a square of its own page colour first (Florence squeezes to 768²: a wide title strip became "1"), lines run together are re-spaced (aB → a B, before "("), a run-on subtitle is cut off the title. Tested with the real model (CPU, headless): all 7 headings and 10 row labels right but one letter ("Anistic"), ~3 minutes on a CPU. Headless file:// does not keep the transformers cache between runs (the test pretends it is downloaded).

- Per-picture background (right-click a box): How much background to take (ctol 12/24/40/60 → splitSheet tolerance on its own box), Fill its shape (convex hull of the kept pixels, restored from the sheet: a silver drive's top face on light grey), Magic wand erase/keep from the clicked point (4-way flood on the sheet within 30 of the seed colour; several, Undo the last wand). Cells (table/grid) are cut both ways by themselves: when cutting out keeps < 85% of what the strict whole-cell clear keeps (and that one did clear ≥ 15%), the whole-cell one is used (realistic pictures' highlights on white).
- See-through is now ≥ 1% of pixels with alpha < 128 (splitSheet, prep): the AI-made PNGs are alpha 251–253 all over, which made a whole cell count as picture (a white cell kept, 100% solid).
- Touch up (fifth tool; was Keep solid): marks = { pts (sheet px polygon), op keep|erase, side in|out }, applied after everything automatic, in order (applyMarks: canvas-filled polygon mask; keep = sheet pixels back, erase = alpha 0; outside = the rest of the picture whose box holds the mark's middle). Shapes: Box, Ellipse (48-point polygon), Lasso the Photoshop way (drag = freehand, closes on release when begun with a drag; click/Shift-click = straight corners; first corner, double-click or Enter closes; Backspace, Escape; Alt = erase for that one). Click one to remove; Undo the last touch-up; Clear. Names/Boxes toggles in the toolbar (N, B). For the odd picture whose face is the page's colour (the user's silver drive, cell 55).
- Resets (right-click): Reset this picture (moved, prefs, split, touch-ups whose middle is in it), Reset the whole sheet (all hand changes, autoCut again; labels/headings/title read are kept). Box menu shortened: Background submenu (amount, touch up, fill shape, wand, shadow, cut/whole). Menus no longer close when scrolled inside.
